# kenedydev

GitHub profile repository: the root `README.md` is the profile page.

## Profile art

| File | Role |
| --- | --- |
| `src/profile-wall.svg` | Vector source of the scene. Edit this one. |
| `assets/profile-wall.svg` | Generated by `scripts/bake.py`; this is what the README shows. Do not edit it by hand. |
| `src/{website,linkedin,github,email}.svg` | Vector sources of the contact stickers below the wall. |
| `assets/{website,linkedin,github,email}.svg` | Generated from them with `python3 scripts/bake.py src/NAME.svg assets/NAME.svg`. Do not edit them by hand. |

### Workflow

1. Edit `src/profile-wall.svg`.
2. Run `python3 scripts/bake.py`. It renders source and output in a static frame (on dark and light backgrounds) and at the middle of every span between keyframes (on dark, with all animations started together), then compares them in 40×40 px tiles. It writes `assets/profile-wall.svg` only if no tile differs beyond the limit. This catches missing or misplaced parts, not subtle shifts in tone, so always look at the side-by-side pairs in `tmp/bake-check/`, especially around what you changed. To try a change without touching `assets/`, pass explicit paths: `python3 scripts/bake.py SRC OUT`.
3. Commit `src/` and `assets/` together.

Requirements: Chromium (or `CHROMIUM=/path/to/chrome`) and the packages in `scripts/requirements.txt`, installed in a virtualenv or through the system package manager.

### Why bake

Inside an `<img>`, SVG filters (turbulence, blur, filtered masks) are recomputed on every animation change and make the page stutter. `bake.py` replaces the parts marked with `data-bake` with embedded WebP. A filter left outside a marked layer makes the script fail.

### `data-bake` layers

- `data-bake="name"` renders the element and everything inside it into one image. Its `id` and `class` move to a `<g>` around the image, so its CSS keeps working there.
- The element's own `transform`, `filter`, `mask`, `clip-path` and `opacity` go into the image.
- On ancestors above the outermost layer (set these as attributes, not in `style=`):
  - `transform` stays and is compensated for.
  - `mask` and `clip-path` stay live. They need user-space units: `maskUnits="userSpaceOnUse"` with `x`, `y`, `width` and `height`, and no `clipPathUnits="objectBoundingBox"`. The mask becomes an image.
  - `filter` and `opacity` go into the image and are removed from the ancestor, so they may cover only one layer and no unmarked content.
- A layer inside a layer (such as `lit-first-e` inside `lit`) becomes its own image, drawn above the outer one. Effects between the two apply to each image separately. Only one level of nesting is allowed. Use it for a part that animates on its own.
- Elements with the same name become one image. They must share their classes and have at most one `id`. At the top level they must be consecutive siblings.
- An `id` inside a layer is gone in the output, except the `id` of the marked element itself. A `<use>` may point at that `id`, as the glitch `slices` do with `#lit`.
- `data-bake-scale` (greater than 0, up to 1, default 1) lowers the resolution of the image, which is rendered at 2x. `data-bake-quality` is the WebP quality (0 to 100, default 80). Both also work on an ancestor `<mask>`, where the default scale is 0.5. Blurred parts can take a low scale. Text and the neon tubes need 1.

### Scene rules

- For GitHub: no JavaScript, no `<foreignObject>`, no external fonts or files. All text is converted to paths.
- Every animation sits inside `@media (prefers-reduced-motion: no-preference)`.
- Animations must use `steps(n)` (or `step-start` / `step-end`). A continuous timing (`ease`, `linear`) makes the browser redraw the scene on every frame, so the script refuses it.
- Layers and masks are rendered without CSS, so the static look inside them must be set with attributes. A class or `#id` with a CSS rule inside a layer or mask, without its own `data-bake`, is an error, because it would be frozen.
- Do not animate `transform` through CSS on a marked element that has a `transform` attribute: both would add up in the output, and the script refuses it.
- When visible text changes, update the SVG `<desc>` (`<title>` in the contact stickers) and the `alt` in `README.md` too.

### Contact stickers

- Each icon glows in the color of its link: the brand color, the highlight color of kenedy.dev for the website, and amber for email, which has none.
- Each sticker has its own flicker period and pattern, so the icons never blink together. Keep them out of sync.
- The four must fit in one row in the README column, which is about as wide as the wall (880 px), gaps included.

### Text

Fonts are not kept in the repository.

- KENEDY and "a developer" are stroked centerlines, not font glyphs. To change them, edit the paths: `#k-pink`, `#e1-pink` and `#nedy-pink` (pink) and `#k-cyan` and `#enedy-cyan` (cyan) for KENEDY, clipped by `#name-clip`; `#subtitle-fixed-tubes` and `#subtitle-o` for the subtitle. KENEDY was traced from Train One, whose strokes are pairs of parallel lines: the outer line became pink and the inner one cyan. The subtitle was drawn by hand.
- For the other texts, download the font from Google Fonts and convert the glyphs to paths (for example with `fontTools`), at the size and position of the current path. The spray texts have per-letter jitter, so a plain conversion looks cleaner than the text around it.
